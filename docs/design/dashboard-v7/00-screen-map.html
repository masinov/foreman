Screen map

Structure only. Four levels, each with one page. You are always at exactly one of them, and the breadcrumb says which: Workspace / Project / Sprint / Task.

1 Workspace 2 Project 3 Sprint 4 Task
What it is This installation. The only place that spans projects. One repository being worked on. The unit you run, pause and configure. A batch of tasks with a goal. One is active per project. One piece of work on its own branch.
The page shows
  • Needs you, across projects, each item naming its project
  • Projects: engine state, active sprint, open counts
  • Engine: state, current task, start, pause, stop
  • Needs you, in this project
  • Tabs: Sprints, Backlog, Activity
  • Backlog: filed work, unaccepted first, then accepted and waiting to be planned
  • Project settings: a separate page reached from the title row, not a tab. General, and Workflow (the stages, the role at each, and the evidence a task needs to finish)
  • Activity: milestones only
  • Goal and totals
  • Tasks, as a list or a board
  • Activity: milestones plus each step
  • The pending decision, if any, with its facts
  • Tabs: Overview, Changes, Checks, Activity
  • Checks holds tests, review, criteria, and evidence files (screenshots, recordings)

  • Open the manager

  • Open the manager

Goes down to A project. An item in Needs you goes straight to its task. A sprint. An item in Needs you goes straight to its task. A task. Nothing below.
Settings here Its own page: default roles and workflows, access tokens and identity, notification channels, runners, and this machine's values. Who decides, limits, models, notifications, intake tokens. Its own roles and workflows where it overrides the defaults, read from the default branch. Machine-level values are shown, changed from a terminal. Whether Foreman picks its own tasks in this sprint. Overrides for this task: who decides, which model for a step.

Not screens

Manager
The project's assistant. One conversation per project. A side bar on the right of the project, sprint and task pages, toggled from the top bar and remembered. It knows which page you are on. It proposes actions and you confirm them. It does not exist at workspace level.
Engine
One per project. Its state is in the project header on every page inside that project, and in the project's row on the workspace page.
Project switcher
The first breadcrumb segment lists your projects, each with its count of items needing you.

Needs you: one list, four kinds of item

  • Accept filed work. A system, an agent or a person filed a task into the backlog; it cannot be planned until accepted.
  • Approve a plan. Before development starts.
  • Approve a merge. After tests and review.
  • Unblock. The engine parked a task and says why.

Which of the first three ever reach you is the project's "who decides" setting. The same list appears at workspace level (all projects) and project level (that project).

Decided on 12 Nov

  • One flow for work: filed, accepted, planned into a sprint. The engine runs only the active sprint. A task an agent creates goes to the backlog, not into the running sprint.
  • Projects override roles and workflows. A workflow states what finishing requires, including evidence.
  • Activity is one stream at three depths: project (milestones), sprint (steps), task (everything).
