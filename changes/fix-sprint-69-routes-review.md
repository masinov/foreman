# The independent review of FOR-108: routes are followed everywhere a task moves on

- A person's decision at a human gate takes the route its task's facts choose, and the Activity records it, as the engine's own moves do; it took the first route, so an approval could skip a security review or go round for ever. The branch-moved retest and what a gate card says a decision leads to choose the same way.
- When a review or the tests send work back through routes, the step charged with the failure (and moved up its models) is the one the task goes to, not the first route's.
- A project's `labels` or `path_groups` changed, or a workflow's text saved, is refused when a workflow in use would name what the project does not; one such edit stopped the project's engine.
- A rename counts as both its paths in `changed:` and `changed_only:`; change facts after the merge step are refused (they could never hold); a loop of routing steps alone is refused; a reviewer that can change no file does not count as a step that commits.
- Facts said together read "only docs or tests changed and labelled ui"; the routing step's run reads "Routed".
- The route tests run on Python 3.10, as CI does.
